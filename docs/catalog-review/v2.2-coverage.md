## Part 2: did the original samples already match the chosen patterns?

Each chosen variant became a catalog pattern. This compares the 135 valid
condition-B samples from v2.1 (paraphrased prompts, no reference) with the
pattern for their task, as a whole snippet and by their main function. Reproduce
with `python scripts/catalog_coverage.py --condition B`.

| Task | Pattern | Valid samples | Whole snippet: same shape | same exact | Entry function: same shape | same exact | Closest sample (similarity) |
|---|---|---|---|---|---|---|---|
| jwt_create | `auth.jwt.create_access_token` | 20 | 0 | 0 | 0 | 0 | 0.60 |
| password_hash | `auth.password.pbkdf2` | 20 | 0 | 0 | 0 | 0 | 0.72 |
| paginate_query | `db.pagination.select_page` | 20 | 0 | 0 | 0 | 0 | 0.85 |
| http_retry | `http.get_with_retry.requests` | 20 | 0 | 0 | 0 | 0 | 0.51 |
| env_config | `config.env.load_settings` | 15 | 0 | 0 | 0 | 0 | 0.43 |
| token_bucket | `ratelimit.token_bucket.check` | 20 | 0 | 0 | 0 | 0 | 0.68 |
| csv_import | `importers.users_csv.parse` | 20 | 0 | 0 | 0 | 0 | 0.39 |
| fastapi_create_user | (deferred) | | | | | | |

**None of the 135 samples matched the pattern chosen for its task**, neither as a
whole nor by its main function, and none came within the 0.90 near-shape
similarity. The closest sample per task is 0.39–0.85 similar. Conditions A and C
give the same result: 0 matches. (C's samples converged on the unreviewed v2.1
references, not on these cleaned patterns.)

This is expected, and it is the point: each pattern is a cleaned and reviewed
version (secrets, clocks and transports as parameters, input validation,
resource limits), so it is not any one sample verbatim, including the samples
some patterns were cleaned from. Without the catalog, none of the code generated
for these tasks would be the approved version. With it, v2.1 condition C
suggests a reference in the prompt brings most samples to the reference's
shape (56–100% per task).
