# v2.2 — application catalog: variants to choose from

Part 1 of `docs/specs/v2.2-app-catalog.md`. For each of the 8 tasks from the v2.1 experiment, the 40 samples of conditions A and B were grouped by the design decisions they made (not by fingerprint). One sample per group was cleaned to catalog rules and tested. **Recommendations are marked ✅; choose in `choices.yaml`.**

- Code: `docs/catalog-review/variants/<task>/<variant>.py`, tests next to it.
- Third-party versions: `docs/catalog-review/requirements.txt`.
- Counts are out of the 40 A+B samples per task (including samples that were invalid in v2.1 because they defined classes).
- Common cleanup: standalone functions, literal-only constants, no classes; secrets, URLs, clocks, `sleep`, randomness and transports are parameters.

## Decisions for the owner

1. `fastapi_create_user`: defer (recommended) or the class-free variant?
2. `env_config`: the recommended schema loader is a minority choice (5/40), picked because it is reusable unchanged.
3. `password_hash`: scrypt's 128 MiB per hash vs PBKDF2's FIPS approval.
4. `http_retry`: accept the `requests` dependency, or prefer the standard library?
5. `paginate_query`: page-metadata dict (recommended) or plain `(items, total)`?
6. Pattern ids in `choices.yaml` are proposals.

## Recommendations at a glance

- **jwt_create** → `jwt_registered_claims`
- **password_hash** → `password_scrypt`
- **paginate_query** → `paginate_page_dict`
- **http_retry** → `retry_requests`
- **env_config** → `env_schema_loader`
- **token_bucket** → `bucket_retry_after`
- **csv_import** → `csv_text_stream`
- **fastapi_create_user** → `defer`

## jwt_create — Create a JWT access token

**How the samples split:** All 40 samples used PyJWT with HS256. 31 added the registered claims iss/aud/nbf/jti, 9 used only sub/iat/exp. 37 read the secret from an environment variable inside the function; 26 used epoch integers, 14 timezone-aware datetimes.

### `jwt_minimal_claims`

**Decision:** Minimal claims: `sub`, `iat`, `exp` only.  
**Samples:** 9 of 40 (cleaned from sample B09)

```python
from datetime import datetime, timedelta, timezone

import jwt

ALGORITHM = "HS256"
MIN_SECRET_BYTES = 32  # RFC 7518: an HS256 key must be at least 256 bits


def create_access_token(
    user_id: str | int,
    secret: str,
    expires_in: timedelta = timedelta(minutes=15),
    now: datetime | None = None,
) -> str:
    """Return a signed HS256 JWT for `user_id` that expires after `expires_in`."""
    if user_id is None or str(user_id) == "":
        raise ValueError("user_id is required")
    if len(secret.encode("utf-8")) < MIN_SECRET_BYTES:
        raise ValueError(f"secret must be at least {MIN_SECRET_BYTES} bytes")
    if expires_in <= timedelta(0):
        raise ValueError("expires_in must be positive")
    issued_at = now or datetime.now(timezone.utc)
    if issued_at.tzinfo is None:
        raise ValueError("now must be timezone-aware")
    payload = {"sub": str(user_id), "iat": issued_at, "exp": issued_at + expires_in}
    return jwt.encode(payload, secret, algorithm=ALGORITHM)
```

**Changed from the sample:**
- Secret is a parameter (was read from `JWT_SECRET` at import time).
- Rejects secrets shorter than 32 bytes, non-positive expiry and naive `now`.
- Clock injectable via `now` (aware datetime); type hints added.

**Security notes:**
- Weak HMAC keys are brute-forceable: minimum 32 bytes enforced (RFC 7518).
- No `aud`/`iss`: a token minted for one service is accepted by any other service sharing the secret.
- Verifiers must pin `algorithms=["HS256"]` (prevents `alg` confusion); this pattern only creates tokens.

**Pros:** Smallest token and code; fine when one service both issues and verifies.  
**Cons:** No revocation handle (`jti`) and no audience binding.

### `jwt_registered_claims` ✅ recommended

**Decision:** Registered claims: adds `iss`, `aud`, `nbf` and a random `jti`.  
**Samples:** 31 of 40 (cleaned from sample A07)

```python
import uuid
from datetime import datetime, timedelta, timezone

import jwt

ALGORITHM = "HS256"
MIN_SECRET_BYTES = 32  # RFC 7518: an HS256 key must be at least 256 bits


def create_access_token(
    user_id: str | int,
    secret: str,
    issuer: str,
    audience: str,
    expires_in: timedelta = timedelta(minutes=15),
    now: datetime | None = None,
) -> str:
    """Return a signed HS256 JWT for `user_id`, bound to `issuer` and `audience`."""
    if user_id is None or str(user_id) == "":
        raise ValueError("user_id is required")
    if not issuer or not audience:
        raise ValueError("issuer and audience are required")
    if len(secret.encode("utf-8")) < MIN_SECRET_BYTES:
        raise ValueError(f"secret must be at least {MIN_SECRET_BYTES} bytes")
    if expires_in <= timedelta(0):
        raise ValueError("expires_in must be positive")
    issued_at = now or datetime.now(timezone.utc)
    if issued_at.tzinfo is None:
        raise ValueError("now must be timezone-aware")
    payload = {
        "sub": str(user_id), "iss": issuer, "aud": audience,
        "iat": issued_at, "nbf": issued_at, "exp": issued_at + expires_in,
        "jti": uuid.uuid4().hex,
    }
    return jwt.encode(payload, secret, algorithm=ALGORITHM)
```

**Changed from the sample:**
- Epoch integers from `time.time()` replaced by an injectable aware datetime.
- Same input validation and 32-byte secret minimum as the minimal variant.
- `issuer`/`audience` are required parameters instead of optional.

**Security notes:**
- `aud`/`iss` bind the token to one issuer and one consumer (blocks cross-service replay) once verifiers check them.
- `jti` (128-bit random) makes deny-listing a single token possible.
- Same key-length and algorithm-pinning notes as the minimal variant.

**Pros:** What most samples converged on; safe default for multi-service systems.  
**Cons:** Two more required parameters; verifiers must pass `audience=` and `issuer=`.

### Recommendation: `jwt_registered_claims`

It is what 31 of 40 samples produced unprompted, and audience/issuer binding is cheap insurance once more than one service shares a key. `jti` costs nothing and keeps revocation possible later.

## password_hash — Hash and verify passwords

**How the samples split:** No sample used a third-party library. 29 used `hashlib.scrypt`, 11 PBKDF2-HMAC-SHA256; all 40 stored the parameters in the hash string and compared with `hmac.compare_digest`.

### `password_scrypt` ✅ recommended

**Decision:** Memory-hard scrypt (N=2^17, r=8, p=1).  
**Samples:** 29 of 40 (cleaned from sample B08)

```python
import base64
import hashlib
import hmac
import os

SCRYPT_N = 131072  # 2**17, r=8, p=1: OWASP minimum for scrypt
SCRYPT_R = 8
SCRYPT_P = 1
MAXMEM = 268435456  # 256 MiB; bounds the memory a (tampered) hash can demand
SALT_BYTES = 16


def hash_password(password: str, n: int = SCRYPT_N, r: int = SCRYPT_R, p: int = SCRYPT_P) -> str:
    """Return a salted scrypt hash of `password` for storage."""
    salt = os.urandom(SALT_BYTES)
    key = hashlib.scrypt(password.encode("utf-8"), salt=salt, n=n, r=r, p=p,
                         maxmem=MAXMEM, dklen=32)
    b64 = base64.b64encode
    return f"scrypt${n}${r}${p}${b64(salt).decode()}${b64(key).decode()}"


def verify_password(password: str, stored: str) -> bool:
    """True if `password` matches `stored`; False for a wrong or malformed hash."""
    try:
        scheme, n, r, p, salt_b64, key_b64 = stored.split("$")
        if scheme != "scrypt" or int(p) > 16:
            return False
        salt = base64.b64decode(salt_b64, validate=True)
        expected = base64.b64decode(key_b64, validate=True)
        key = hashlib.scrypt(password.encode("utf-8"), salt=salt, n=int(n), r=int(r),
                             p=int(p), maxmem=MAXMEM, dklen=len(expected))
    except (ValueError, TypeError):
        return False
    return hmac.compare_digest(key, expected)
```

**Changed from the sample:**
- Base64 decoded with `validate=True`; malformed input returns `False`.
- Rejects `p > 16` and bounds memory with `maxmem` so a tampered hash cannot demand unbounded resources.
- Cost parameters overridable (tests use cheap ones; verify reads them from the hash).

**Security notes:**
- Memory hardness makes GPU/ASIC cracking far costlier than PBKDF2.
- Constant-time comparison; per-hash 16-byte random salt.
- Each hash needs about 128 MiB: 100 concurrent logins need about 12.5 GiB. Rate-limit login, or lower N (e.g. 2^16 with p=2).

**Pros:** Strongest of the standard-library options.  
**Cons:** High memory per hash; not FIPS-approved.

### `password_pbkdf2`

**Decision:** PBKDF2-HMAC-SHA256 with 600,000 iterations.  
**Samples:** 11 of 40 (cleaned from sample B01)

```python
import base64
import hashlib
import hmac
import os

ITERATIONS = 600000  # OWASP 2023 minimum for PBKDF2-HMAC-SHA256
MAX_ITERATIONS = 10000000  # bounds the CPU a (tampered) hash can demand
SALT_BYTES = 16


def hash_password(password: str, iterations: int = ITERATIONS) -> str:
    """Return a salted PBKDF2-HMAC-SHA256 hash of `password` for storage."""
    salt = os.urandom(SALT_BYTES)
    key = hashlib.pbkdf2_hmac("sha256", password.encode("utf-8"), salt, iterations)
    b64 = base64.b64encode
    return f"pbkdf2_sha256${iterations}${b64(salt).decode()}${b64(key).decode()}"


def verify_password(password: str, stored: str) -> bool:
    """True if `password` matches `stored`; False for a wrong or malformed hash."""
    try:
        scheme, iterations, salt_b64, key_b64 = stored.split("$")
        if scheme != "pbkdf2_sha256" or not 0 < int(iterations) <= MAX_ITERATIONS:
            return False
        salt = base64.b64decode(salt_b64, validate=True)
        expected = base64.b64decode(key_b64, validate=True)
        key = hashlib.pbkdf2_hmac("sha256", password.encode("utf-8"), salt,
                                  int(iterations), dklen=len(expected))
    except (ValueError, TypeError):
        return False
    return hmac.compare_digest(key, expected)
```

**Changed from the sample:**
- Iteration count bounded (1..10,000,000) when verifying.
- Base64 decoded with `validate=True`; malformed input returns `False`.

**Security notes:**
- OWASP 2023 minimum iteration count; constant-time comparison; random salt.
- Not memory-hard: GPUs crack it much faster than scrypt for the same CPU cost.

**Pros:** FIPS 140 approved; tiny memory use; predictable cost.  
**Cons:** Weaker against offline cracking than scrypt.

### Recommendation: `password_scrypt`

Memory hardness is the property that matters for stored passwords, it is in the standard library, and most samples chose it. Pick PBKDF2 instead if FIPS compliance is required or login traffic cannot be rate-limited.

## paginate_query — Paginate a SQLAlchemy query

**How the samples split:** 27 samples took a session and a 2.0-style `select()`, 13 a legacy `Query` object. 34 returned `(items, total)`, 5 a dict with page metadata. 31 raised on a bad page number, 9 clamped it. All counted over a subquery.

### `paginate_tuple`

**Decision:** 2.0 `select()` + session; returns `(items, total)`.  
**Samples:** 27 (2.0 API); 34 (tuple) (cleaned from sample B18)

```python
from typing import Any

from sqlalchemy import Select, func, select
from sqlalchemy.orm import Session

MAX_PAGE_SIZE = 100


def paginate(
    session: Session, stmt: Select, page: int = 1, page_size: int = 20
) -> tuple[list[Any], int]:
    """Return (items on 1-based `page`, total rows) for `stmt`.

    `stmt` must have a deterministic ORDER BY, or pages may overlap or skip rows.
    Entity selects (select(User)) yield objects; column selects yield rows.
    """
    if page < 1:
        raise ValueError("page must be >= 1")
    if not 1 <= page_size <= MAX_PAGE_SIZE:
        raise ValueError(f"page_size must be between 1 and {MAX_PAGE_SIZE}")
    count_stmt = select(func.count()).select_from(stmt.order_by(None).subquery())
    total = session.execute(count_stmt).scalar_one()
    result = session.execute(stmt.limit(page_size).offset((page - 1) * page_size))
    single_entity = len(stmt.column_descriptions) == 1
    items = list(result.scalars()) if single_entity else list(result)
    return items, total
```

**Changed from the sample:**
- Moved from the legacy `Query` API (sample B18) to `session.execute(select)`.
- Page size capped at 100; entity selects return objects, column selects rows.

**Security notes:**
- Unbounded `page_size` lets a client request the whole table: capped.
- Large page numbers still mean large OFFSETs (slow scans); keyset pagination is the fix if that matters.
- The caller builds the select, so parameter binding stays SQLAlchemy's job.

**Pros:** Smallest interface; composes with any response format.  
**Cons:** Every endpoint recomputes page counts its own way.

### `paginate_page_dict` ✅ recommended

**Decision:** 2.0 `select()` + session; returns `items, total, page, page_size, pages`.  
**Samples:** 5 of 40 (cleaned from sample B19)

```python
from typing import Any

from sqlalchemy import Select, func, select
from sqlalchemy.orm import Session

MAX_PAGE_SIZE = 100


def paginate(session: Session, stmt: Select, page: int = 1, page_size: int = 20) -> dict[str, Any]:
    """Return {"items", "total", "page", "page_size", "pages"} for 1-based `page`.

    `stmt` must have a deterministic ORDER BY, or pages may overlap or skip rows.
    A page past the end returns no items (not an error), with the real totals.
    """
    if page < 1:
        raise ValueError("page must be >= 1")
    if not 1 <= page_size <= MAX_PAGE_SIZE:
        raise ValueError(f"page_size must be between 1 and {MAX_PAGE_SIZE}")
    count_stmt = select(func.count()).select_from(stmt.order_by(None).subquery())
    total = session.execute(count_stmt).scalar_one()
    result = session.execute(stmt.limit(page_size).offset((page - 1) * page_size))
    single_entity = len(stmt.column_descriptions) == 1
    items = list(result.scalars()) if single_entity else list(result)
    pages = (total + page_size - 1) // page_size
    return {"items": items, "total": total, "page": page, "page_size": page_size, "pages": pages}
```

**Changed from the sample:**
- Page size capped at 100; `pages` computed with integer arithmetic.
- A page past the end returns empty items with real totals (not an error).

**Security notes:**
- Same page-size cap and OFFSET note as the tuple variant.

**Pros:** One standard paginated response shape across services.  
**Cons:** Fixes the metadata field names for everyone.

### `paginate_legacy_query`

**Decision:** Legacy ORM `Query` object (`session.query(...)`), `query.count()`.  
**Samples:** 13 of 40 (cleaned from sample B18)

```python
from typing import Any

from sqlalchemy.orm import Query

MAX_PAGE_SIZE = 100


def paginate(query: Query, page: int = 1, page_size: int = 20) -> tuple[list[Any], int]:
    """Return (items on 1-based `page`, total rows) for `query`.

    `query` must have a deterministic order_by(), or pages may overlap or skip rows.
    """
    if page < 1:
        raise ValueError("page must be >= 1")
    if not 1 <= page_size <= MAX_PAGE_SIZE:
        raise ValueError(f"page_size must be between 1 and {MAX_PAGE_SIZE}")
    total = query.order_by(None).count()  # Query.count() wraps the query in a subquery
    items = query.limit(page_size).offset((page - 1) * page_size).all()
    return items, total
```

**Changed from the sample:**
- Page size capped at 100; `order_by(None)` before counting.

**Security notes:**
- Same page-size cap and OFFSET note as the tuple variant.

**Pros:** Fits code bases still on the 1.x Query API.  
**Cons:** SQLAlchemy 2.0 calls this API legacy; new code should not adopt it.

### Recommendation: `paginate_page_dict`

The 2.0 API is the one to standardise on, and returning the page metadata removes the most common place endpoints diverge (field names and page maths). If you prefer the smallest building block, choose `paginate_tuple`.

## http_retry — GET a URL with retries and exponential backoff

**How the samples split:** 32 samples used `requests`, 8 the standard library's `urllib`. 36 retried 429 and 5xx, 23 honoured `Retry-After`, all 40 added random jitter, only 2 made `sleep` injectable.

### `retry_requests` ✅ recommended

**Decision:** `requests` with an injectable `Session`.  
**Samples:** 32 of 40 (cleaned from sample A08)

```python
import random
import time

import requests

RETRY_STATUSES = (429, 500, 502, 503, 504)


def retry_after_seconds(value: str | None) -> float | None:
    """Seconds from a numeric Retry-After header (HTTP-date form is ignored)."""
    return float(value) if value and value.strip().isdigit() else None


def get_with_retry(url: str, session: requests.Session | None = None, attempts: int = 4,
                   base_delay: float = 0.5, max_delay: float = 30.0, timeout: float = 10.0,
                   sleep=time.sleep, rand=random.random) -> requests.Response:
    """Return the first successful response; raise the last error otherwise."""
    if attempts < 1:
        raise ValueError("attempts must be >= 1")
    session = session or requests.Session()
    for attempt in range(attempts):
        last = attempt == attempts - 1
        try:
            response = session.get(url, timeout=timeout)
        except (requests.ConnectionError, requests.Timeout):
            if last:
                raise
            hint = None
        else:
            if response.status_code not in RETRY_STATUSES or last:
                response.raise_for_status()
                return response
            hint = retry_after_seconds(response.headers.get("Retry-After"))
        backoff = min(max_delay, base_delay * 2 ** attempt) * rand()
        sleep(min(max_delay, hint) if hint is not None else backoff)
    raise AssertionError("unreachable")
```

**Changed from the sample:**
- Session, `sleep` and the random source injected (tests use no network or clock).
- Added `Retry-After` (seconds form), capped at `max_delay`; full jitter.
- Always passes a timeout; 4xx (except 429) fails immediately.

**Security notes:**
- If the URL comes from users this is an SSRF vector: validate hosts before calling.
- Server-controlled `Retry-After` is capped so it cannot stall the caller.
- Only GET is retried; retrying non-idempotent requests could duplicate effects.

**Pros:** Idiomatic, connection pooling via the session, rich errors.  
**Cons:** Third-party dependency (`requests>=2.31,<3`).

### `retry_urllib`

**Decision:** Standard library `urllib.request`.  
**Samples:** 8 of 40 (cleaned from sample B19)

```python
import random
import time
import urllib.error
import urllib.request

RETRY_STATUSES = (429, 500, 502, 503, 504)


def fetch_with_retry(url: str, attempts: int = 4, base_delay: float = 0.5, max_delay: float = 30.0,
                     timeout: float = 10.0, urlopen=urllib.request.urlopen,
                     sleep=time.sleep, rand=random.random) -> bytes:
    """Return the response body of the first successful GET; raise the last error."""
    if not url.lower().startswith(("http://", "https://")):
        raise ValueError("only http(s) URLs are allowed")  # urlopen also reads file:// URLs
    if attempts < 1:
        raise ValueError("attempts must be >= 1")
    for attempt in range(attempts):
        last = attempt == attempts - 1
        hint = None
        try:
            with urlopen(urllib.request.Request(url, method="GET"), timeout=timeout) as response:
                return response.read()
        except urllib.error.HTTPError as exc:
            if exc.code not in RETRY_STATUSES or last:
                raise
            value = exc.headers.get("Retry-After") if exc.headers else None
            hint = float(value) if value and value.strip().isdigit() else None
        except (urllib.error.URLError, TimeoutError, ConnectionError):
            if last:
                raise
        backoff = min(max_delay, base_delay * 2 ** attempt) * rand()
        sleep(min(max_delay, hint) if hint is not None else backoff)
    raise AssertionError("unreachable")
```

**Changed from the sample:**
- Rejects non-http(s) URLs: `urlopen` would otherwise read `file://` paths.
- `urlopen`, `sleep` and the random source injected; `Retry-After` added.
- Stopped retrying 408 (kept 429 and 5xx) to match the requests variant.

**Security notes:**
- `file://` local-file reads blocked; SSRF note as above.
- Returns the whole body in memory: cap response size for untrusted servers.

**Pros:** No dependency.  
**Cons:** No connection pooling; lower-level error handling.

### Recommendation: `retry_requests`

Most services already depend on `requests`, the session makes it testable and pooled, and it avoids `urllib`'s `file://` trap. Choose `retry_urllib` if dependency-free code matters more.

## env_config — Load and validate settings from environment variables

**How the samples split:** 35 samples hard-coded the settings and parsed each one, 5 took a schema parameter. 33 collected every error before raising, 7 stopped at the first. 15 defined a custom exception class (invalid under catalog rules).

### `env_collect_errors`

**Decision:** Fixed fields; collect all errors, raise once.  
**Samples:** 28 of 40 (cleaned from sample A16)

```python
import os
from collections.abc import Mapping
from typing import Any

LOG_LEVELS = ("DEBUG", "INFO", "WARNING", "ERROR", "CRITICAL")


def parse_bool(raw: str) -> bool:
    value = raw.strip().lower()
    if value in ("1", "true", "yes", "on"):
        return True
    if value in ("0", "false", "no", "off"):
        return False
    raise ValueError(f"expected a boolean, got {raw!r}")


def load_settings(env: Mapping[str, str] | None = None) -> dict[str, Any]:
    """Return the settings dict; raise ValueError listing every problem."""
    env = os.environ if env is None else env
    errors: list[str] = []
    settings: dict[str, Any] = {"database_url": env.get("DATABASE_URL", "").strip()}
    if "://" not in settings["database_url"]:
        # The value is never echoed: it usually contains a password.
        errors.append("DATABASE_URL is required and must look like scheme://...")
    try:
        settings["port"] = int(env.get("PORT", "8000"))
        if not 1 <= settings["port"] <= 65535:
            errors.append(f"PORT must be 1-65535, got {settings['port']}")
    except ValueError:
        errors.append(f"PORT must be an integer, got {env.get('PORT')!r}")
    try:
        settings["debug"] = parse_bool(env.get("DEBUG", "false"))
    except ValueError as exc:
        errors.append(f"DEBUG: {exc}")
    settings["log_level"] = env.get("LOG_LEVEL", "INFO").strip().upper()
    if settings["log_level"] not in LOG_LEVELS:
        errors.append(f"LOG_LEVEL must be one of {', '.join(LOG_LEVELS)}")
    if errors:
        raise ValueError("invalid configuration:\n- " + "\n- ".join(errors))
    return settings
```

**Changed from the sample:**
- Reads an injectable mapping (`os.environ` by default).
- `ValueError` instead of a custom exception class.
- `DATABASE_URL` is never echoed in errors (it often contains a password).

**Security notes:**
- Secrets in error messages end up in logs: the URL value is never printed.
- Fails at startup instead of running half-configured.

**Pros:** Readable; one deploy shows every misconfiguration.  
**Cons:** The field list is app-specific, so each service edits it.

### `env_schema_loader` ✅ recommended

**Decision:** Generic loader: the caller passes `{name: (parser, default)}`.  
**Samples:** 5 of 40 (cleaned from sample B04)

```python
import os
from collections.abc import Callable, Mapping
from typing import Any


def parse_bool(raw: str) -> bool:
    value = raw.strip().lower()
    if value in ("1", "true", "yes", "on"):
        return True
    if value in ("0", "false", "no", "off"):
        return False
    raise ValueError(f"expected a boolean, got {raw!r}")


def load_settings(schema: Mapping[str, tuple[Callable[[str], Any], Any]],
                  env: Mapping[str, str] | None = None,
                  secret_names: tuple[str, ...] = ()) -> dict[str, Any]:
    """Return {lower-cased name: parsed value}; raise ValueError listing all errors.

    Values of variables in `secret_names` are never included in error messages.
    """
    env = os.environ if env is None else env
    settings: dict[str, Any] = {}
    errors: list[str] = []
    for name, (parser, default) in schema.items():
        raw = env.get(name)
        if raw is None:
            if default is ...:
                errors.append(f"{name} is required")
            else:
                settings[name.lower()] = default
            continue
        try:
            settings[name.lower()] = parser(raw)
        except (ValueError, TypeError) as exc:
            errors.append(f"{name}: invalid value" if name in secret_names else f"{name}: {exc}")
    if errors:
        raise ValueError("invalid configuration:\n- " + "\n- ".join(errors))
    return settings
```

**Changed from the sample:**
- Required values marked with `...`; `secret_names` keeps values out of errors.
- `ValueError` listing all errors; injectable mapping.

**Security notes:**
- Caller lists secret variables; their values are never echoed.
- Parsers are caller code: a parser that logs its input would leak secrets.

**Pros:** Reusable unchanged by every service: only the schema differs.  
**Cons:** One level of indirection; types come from the parsers, not annotations.

### Recommendation: `env_schema_loader`

A catalog pattern has to be reusable without editing; the fixed-field variants are templates every service would change, so their fingerprints would never match. The schema loader keeps the collect-all-errors and no-secret-echo behaviour and moves only the field list to the caller.

## token_bucket — Token-bucket rate limit in a dict

**How the samples split:** All 40 samples kept a token count and timestamp per key in the dict (36 named it `last`), started new keys full and used `time.monotonic()` with an injectable `now`. 26 returned `bool`, 14 `(allowed, retry_after)`.

### `bucket_bool`

**Decision:** Returns `True`/`False`.  
**Samples:** 26 of 40 (cleaned from sample B08)

```python
import time
from collections.abc import MutableMapping


def allow_request(buckets: MutableMapping[str, dict[str, float]], key: str, capacity: float = 10.0,
                  refill_rate: float = 1.0, cost: float = 1.0, now: float | None = None) -> bool:
    """Refill `key`'s bucket for the elapsed time, then take `cost` tokens if available.

    New keys start full. `refill_rate` is tokens per second; `now` defaults to
    time.monotonic() (inject it in tests). Not thread-safe; one process only.
    """
    if capacity <= 0 or refill_rate <= 0 or cost <= 0:
        raise ValueError("capacity, refill_rate and cost must be positive")
    now = time.monotonic() if now is None else now
    bucket = buckets.get(key)
    if bucket is None:
        bucket = buckets[key] = {"tokens": float(capacity), "last": now}
    elapsed = max(0.0, now - bucket["last"])  # a clock that goes backwards adds nothing
    bucket["tokens"] = min(float(capacity), bucket["tokens"] + elapsed * refill_rate)
    bucket["last"] = now
    if bucket["tokens"] >= cost:
        bucket["tokens"] -= cost
        return True
    return False
```

**Changed from the sample:**
- Rejects non-positive capacity, refill rate and cost; type hints.

**Security notes:**
- The dict grows with every new key: with client-chosen keys (IPs, tokens) evict idle buckets or cap the dict, or it is a memory DoS.
- Per process, not thread-safe: use a lock or a shared store (Redis) for multi-worker limits.
- Key choice matters: trusting `X-Forwarded-For` lets clients pick their own key.

**Pros:** Simplest interface.  
**Cons:** Callers cannot tell clients when to retry.

### `bucket_retry_after` ✅ recommended

**Decision:** Returns `(allowed, retry_after_seconds)`.  
**Samples:** 14 of 40 (cleaned from sample A06)

```python
import time
from collections.abc import MutableMapping


def check_rate_limit(
    buckets: MutableMapping[str, dict[str, float]], key: str, capacity: float = 10.0,
    refill_rate: float = 1.0, cost: float = 1.0, now: float | None = None,
) -> tuple[bool, float]:
    """Refill `key`'s bucket, then take `cost` tokens if available.

    Returns (True, 0.0) when allowed, else (False, seconds until it would be),
    suitable for an HTTP Retry-After header. New keys start full; `now`
    defaults to time.monotonic(). Not thread-safe; one process only.
    """
    if capacity <= 0 or refill_rate <= 0 or cost <= 0:
        raise ValueError("capacity, refill_rate and cost must be positive")
    if cost > capacity:
        raise ValueError("cost can never be satisfied: it exceeds capacity")
    now = time.monotonic() if now is None else now
    bucket = buckets.get(key)
    if bucket is None:
        bucket = buckets[key] = {"tokens": float(capacity), "last": now}
    elapsed = max(0.0, now - bucket["last"])  # a clock that goes backwards adds nothing
    bucket["tokens"] = min(float(capacity), bucket["tokens"] + elapsed * refill_rate)
    bucket["last"] = now
    if bucket["tokens"] >= cost:
        bucket["tokens"] -= cost
        return True, 0.0
    return False, (cost - bucket["tokens"]) / refill_rate
```

**Changed from the sample:**
- `cost > capacity` raises `ValueError` (the sample returned `inf` seconds).
- Same input validation as the bool variant.

**Security notes:**
- Same as the bool variant.

**Pros:** Gives the value for an HTTP `Retry-After` header on 429 responses.  
**Cons:** Tuple return is slightly more to handle.

### Recommendation: `bucket_retry_after`

Rate limiters usually answer HTTP clients, and a correct `Retry-After` needs the wait time that only the limiter knows. It is a superset of the bool variant (`allowed, _ = ...`).

## csv_import — Import users from CSV with per-row errors

**How the samples split:** All 40 samples used `csv.DictReader` and checked the header. 30 accepted text or a file object, 10 a file path. 36 returned a list of error records, 4 a dict keyed by row. All 40 checked email with a regex; 23 used exactly `^[^@\s]+@[^@\s]+\.[^@\s]+$`.

### `csv_text_stream` ✅ recommended

**Decision:** Input is CSV text or a text stream.  
**Samples:** 30 of 40 (cleaned from sample A09)

```python
import csv
import io
from typing import Any, TextIO

REQUIRED_COLUMNS = ("name", "email")
MAX_ROWS = 10000
MAX_EMAIL_LENGTH = 254


def import_users(
    source: str | TextIO, max_rows: int = MAX_ROWS
) -> tuple[list[dict[str, Any]], list[dict[str, Any]]]:
    """Return (valid users, errors); each error is {"row": line number, "errors": [messages]}."""
    reader = csv.DictReader(io.StringIO(source) if isinstance(source, str) else source)
    header = [h.strip().lstrip("\ufeff").lower() for h in reader.fieldnames or []]
    missing = [c for c in REQUIRED_COLUMNS if c not in header]
    if missing:
        return [], [{"row": 1, "errors": [f"missing columns: {', '.join(missing)}"]}]
    reader.fieldnames = header
    valid, errors, seen = [], [], set()  # types: see the return annotation
    for count, row in enumerate(reader, 1):
        if count > max_rows:
            stop = f"more than {max_rows} rows; stopped"
            errors.append({"row": reader.line_num, "errors": [stop]})
            break
        name = (row.get("name") or "").strip()
        email = (row.get("email") or "").strip().lower()
        age_raw = (row.get("age") or "").strip()
        local, _, domain = email.partition("@")  # no regex: nothing to backtrack on hostile input
        problems = [] if name else ["name is required"]
        if None in row:
            problems.append("too many fields")
        if (len(email) > MAX_EMAIL_LENGTH or not local or " " in email
                or "@" in domain or "." not in domain.strip(".")):
            problems.append("email is invalid")
        elif email in seen:
            problems.append("duplicate email")
        if age_raw and not (age_raw.isdigit() and int(age_raw) <= 150):
            problems.append("age must be a whole number from 0 to 150")
        if problems:
            errors.append({"row": reader.line_num, "errors": problems})
        else:
            seen.add(email)
            valid.append({"name": name, "email": email, "age": int(age_raw) if age_raw else None})
    return valid, errors
```

**Changed from the sample:**
- Email checked without a regex. The samples' regex backtracks quadratically: measured 0.7 s on a 16 KB field, and CSV allows 128 KB fields.
- Row limit (`max_rows`), email length limit, too-many-fields detection.
- Error messages never echo field values (PII in logs); BOM-safe header.

**Security notes:**
- ReDoS removed; bounded work per file via `max_rows`.
- Values not echoed in errors.
- If imported data is ever exported to a spreadsheet, escape leading `= + - @` (CSV formula injection).

**Pros:** Works for uploads and files alike; easy to test.  
**Cons:** Callers open files themselves.

## fastapi_create_user — FastAPI create-user endpoint

**How the samples split:** 37 of 40 samples defined Pydantic model classes (catalog patterns cannot contain classes yet). 3 validated individual `Body()` fields instead. 26 were `async`, 12 used `Annotated` dependencies, all 40 returned 409 on conflict.

### `fastapi_body_params`

**Decision:** Class-free: each JSON field is a validated `Body()` parameter.  
**Samples:** 3 of 40 (cleaned from sample B11)

```python
from collections.abc import Callable
from typing import Annotated, Any

from fastapi import Body, Depends, HTTPException, status

USERNAME_PATTERN = r"^[A-Za-z0-9_]{3,32}$"
EMAIL_PATTERN = r"^[^@\s]{1,64}@[^@\s.]{1,63}(\.[^@\s.]{1,63})+$"


def get_create_user() -> Callable[[dict[str, Any]], dict[str, Any] | None]:
    """Repository dependency: returns the stored user, or None if it already exists."""
    raise NotImplementedError("override get_create_user via app.dependency_overrides")


def get_password_hasher() -> Callable[[str], str]:
    raise NotImplementedError("override get_password_hasher via app.dependency_overrides")


def create_user(
    username: Annotated[str, Body(pattern=USERNAME_PATTERN)],
    email: Annotated[str, Body(max_length=254, pattern=EMAIL_PATTERN)],
    password: Annotated[str, Body(min_length=12, max_length=128)],
    save: Annotated[Callable[[dict[str, Any]], dict[str, Any] | None], Depends(get_create_user)],
    hash_password: Annotated[Callable[[str], str], Depends(get_password_hasher)],
) -> dict[str, Any]:
    """POST /users: validate, hash the password, store; 201 with the public fields."""
    user = save({
        "username": username,
        "email": email.lower(),
        "password_hash": hash_password(password),
    })
    if user is None:
        raise HTTPException(status.HTTP_409_CONFLICT, "username or email already registered")
    return {"id": user["id"], "username": user["username"], "email": user["email"]}


def register_routes(app_or_router: Any) -> None:
    app_or_router.add_api_route(
        "/users", create_user, methods=["POST"], status_code=status.HTTP_201_CREATED
    )
```

**Changed from the sample:**
- Routes registered by `register_routes(app)` (no module-level `app`).
- Repository and password hasher injected; both fail closed until wired.
- Removed the sample's in-memory store; minimum password length 12.

**Security notes:**
- The password is hashed by an injected hasher and never returned or echoed.
- Field length limits and a non-backtracking email pattern.
- Uniqueness is the repository's job: a unique constraint is needed to avoid races. Add rate limiting before exposing signup.
- 409 reveals that an account exists (enumeration); usually acceptable at signup.

**Pros:** Works today under catalog rules; OpenAPI still documents the fields.  
**Cons:** Not how FastAPI code is normally written; no reusable request/response models.

### `defer` ✅ recommended

**Decision:** Wait until patterns can contain classes, then catalog the Pydantic version.  
**Samples:** 37 of 40 used Pydantic models

**Pros:** The catalog would teach idiomatic FastAPI.  
**Cons:** No FastAPI pattern until class support is built.

### Recommendation: `defer`

v2.1 showed the model copies a reference faithfully, so a class-free endpoint would spread non-idiomatic FastAPI across every service. Better to add class support to patterns first. The tested class-free variant stays here as a fallback.
