# v1.1 — Canonicalizer fixes

Work unattended. Do not stop to ask questions; when something is ambiguous, pick the simplest reasonable option, record it in `DECISIONS.md`, and continue.

## 0. Before you start

1. Read `CLAUDE.md`, `DECISIONS.md`, `KNOWN_GAPS.md` and `docs/specs/v1-catalog.md`.
2. Save this file verbatim as `docs/specs/v1.1-canonicalizer-fix.md`.
3. Run `pytest` and `pcat validate` to confirm a green starting point.

This phase fixes two gaps from `KNOWN_GAPS.md` and adds a safe way to change canonicalization rules. All v1 invariants in `CLAUDE.md` still hold unless this spec says otherwise.

## 1. Keyword arguments in calls to the pattern's own functions

**Problem:** keyword names at call sites are never renamed, so `f1(v0, reverse=True)` keeps `reverse` while `f1`'s parameter becomes `v1`. Canonical text is then not runnable, and `pcat render --names` can break calls.

**Fix:**
- Before renaming, collect all top-level function definitions in the snippet and their parameters (positional, positional-only, keyword-only), so calls work regardless of definition order.
- For a call whose `func` is a bare `Name` referring to a function defined in the snippet (including the entry point calling itself recursively), rename each keyword argument to that **callee's** placeholder for the matching parameter.
- If a keyword matches no named parameter (the callee takes `**kwargs`), leave it unchanged.
- Calls to anything not defined in the snippet (builtins, imports, attributes, methods) keep their keyword names exactly as before.
- `render` must apply the same logic in reverse: keyword names at calls to snippet functions are rendered using the callee's entry in the name map (`fN.vM` keys for helpers, `vM` for the entry point).
- Update the v1 rule "never rename keyword argument names at call sites" in `CLAUDE.md` and the README to: never rename them except at calls to functions defined in the pattern.

## 2. Module-level constants

**Problem:** patterns cannot contain module-level constants, and `pcat add` silently drops constants a function uses, so the imported pattern's tests fail.

**Fix:**
- Allow top-level `NAME = value` and `NAME: type = value` where `value` is accepted by `ast.literal_eval` (numbers, strings, bytes, booleans, `None`, and tuples, lists, dicts and sets of those). Any other top-level assignment is still rejected with a clear error.
- Rename constants to `c0`, `c1`, … in source order, and rename every reference to them inside functions. Name-map keys are `cN`.
- Constants keep their source position relative to functions in the canonical output; imports stay first as in v1.
- `pcat add` must copy every constant the extracted function and its helpers use (transitively), in source order. If a used module-level name is not a literal constant, fail with a message naming it instead of dropping it silently.
- Remove the corresponding entries from `KNOWN_GAPS.md`.

## 3. Versioning the canonicalization rules

Changing the rules can change fingerprints, so changes must be explicit and auditable.

- Add `CANONICAL_VERSION = 2` in `canonical.py` (v1 rules = 1). Bump it whenever a rule change can alter any fingerprint.
- Write `canonical_version` at the top level of `index.json`.
- Add `pcat migrate-fingerprints`: recompute every pattern's fingerprint under the current rules, rewrite `pattern.yaml` files whose fingerprint changed, regenerate `index.json`, and print a table of `id`, old fingerprint, new fingerprint.
- Update `pcat validate --base <ref>` so a fingerprint change in an approved version is allowed only when **both** `CANONICAL_VERSION` increased relative to `<ref>` **and** that pattern's `impl.py` is byte-identical to `<ref>`. Any change to `impl.py` of an approved version still fails.
- Run the migration on the seed catalog. Report in your final message which seed fingerprints changed (possibly none).

## 4. Tests

Add tests for at least:
- A helper called with keyword arguments: canonical text runs, and calling it gives the same result as the original
- Recursive entry point calling itself with keyword arguments
- Helper defined after the function that calls it
- Callee with `**kwargs`: unmatched keyword is left alone
- External call (`sorted(x, reverse=True)`, `obj.method(key=1)`) keyword names unchanged
- `pcat render --names` renaming a helper parameter keeps calls to it working
- Constants: renamed to `cN`, references updated, round-trip idempotent, non-literal top-level assignment rejected
- `pcat add` on a function that uses a constant and a helper that uses another constant: both copied, imported pattern's tests pass
- `pcat add` failing clearly when a used module-level name is not a literal
- `pcat migrate-fingerprints` reports and rewrites correctly
- `validate --base`: fingerprint change allowed with version bump and unchanged `impl.py`; rejected without the bump; rejected when `impl.py` changed

## 5. Acceptance criteria

- `pytest` passes; `pcat validate` passes; `pcat validate --base HEAD~N` (pointing at the last v1 commit) passes
- For every seed, canonical text is runnable Python and round-trips through `render`
- Seed fingerprints are identical on Python 3.11 and 3.13 (as in v1)
- No v1 test was deleted or weakened; any changed expectation is explained in `DECISIONS.md`
