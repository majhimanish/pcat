## 1. Goal

Answer the project's riskiest question: **does real Python code repeat enough to make a curated catalog worthwhile?** The miner scans repositories, groups code that has the same shape, ranks the groups, shows how much code the catalog already covers, and lets the user promote a group into a catalog pattern through the existing `pcat add` flow.

Build in this order, committing after each part with tests passing: **A** function shapes → **B** fragments → **C** promote → **D** benchmark → **E** handoff.

## 2. Existing behavior to build on

- Canonicalization rules version `CANONICAL_VERSION = 2` in `canonical.py`
- `index.json` format `{"canonical_version": N, "patterns": [...]}`
- Name-map keys `fN`, `vM`, `fN.vM`, `cN`; free names (globals, imports, builtins, attributes) are never renamed
- `pcat add <file.py> --function <name> --id <id>`

Do not change existing canonicalization or fingerprints. Any new normalization lives in new functions. If a change to existing rules seems necessary, don't make it; record it in `KNOWN_GAPS.md` instead.

## 3. Part A — function shape matching

**Shape fingerprint.** Add `shape_canonicalize(source) -> str` and `shape_fingerprint(...)` in a new module `src/pcat/shape.py`:
- Start from the v1.1 canonical form.
- Replace every literal (`int`, `float`, `complex`, `str`, `bytes`) with a typed placeholder: `0` for numbers, `""` for strings, `b""` for bytes. Keep `True`, `False`, `None` and `...` unchanged (they usually change behavior). Docstrings are already gone.
- f-strings: keep the structure, blank the literal parts.
- Constants (`cN`) keep their names but their values become placeholders.
- `shape_fingerprint = sha256(shape_text)`.
- Record `SHAPE_VERSION = 1` in `shape.py` and write it into every report.

**What gets mined.** Every function definition in each file, mined individually: top-level functions, methods (keeping `self`/`cls`) and nested functions. Async functions count. Each mined function is canonicalized on its own, as if it were a one-function snippet: names it doesn't define stay unrenamed. Decorators are dropped from the fingerprint but recorded in the report.

**Filtering (defaults, each switchable by flag).**
- Skip directories: `.git`, `.venv`, `venv`, `site-packages`, `node_modules`, `build`, `dist`, `vendor`, `third_party`, `migrations`, `__pycache__`.
- Skip tests: `tests/`, `test/`, `test_*.py`, `*_test.py`, `conftest.py` (`--include-tests` to include).
- Skip generated files: any of the first 5 lines contains `generated by` or `do not edit` (case-insensitive).
- Skip trivial functions: fewer than `--min-nodes` AST nodes (default 20), or a body that is a single `pass`, `return`, `raise` or `...` statement.
- `--exclude <glob>` (repeatable) for extra exclusions.
- Files that fail to parse or canonicalize are skipped, counted, and listed in the report with the error; they never stop the run.

**Clustering.**
- Group functions by shape fingerprint. A cluster needs at least `--min-occurrences` members (default 3).
- Within a cluster, sub-group members by exact fingerprint (literals included), so the report shows which ones are fully identical.
- Cluster id = `fn-` + first 12 hex characters of the shape fingerprint.
- Score = `(occurrences − 1) × node_count`, an estimate of the code that a pattern would save. Sort by score descending, then by cluster id.
- Also record how many distinct files and distinct top-level input paths each cluster spans.

**Catalog coverage.** For each catalog pattern, compute exact and shape fingerprints for the whole pattern and for its entry-point function alone. A mined function is **covered** if its exact fingerprint matches either one, and **near-covered** if only its shape matches. Report the counts and percentages of mined (non-filtered) functions, and link matching clusters to their catalog ids.

**Command.**
```
pcat mine <path> [<path> …] --out <dir> [--min-nodes N] [--min-occurrences N]
                 [--include-tests] [--exclude GLOB] [--no-fragments] [--jobs N]
```
Writes `<dir>/report.json` and `<dir>/report.html`. Prints a short summary: files scanned, files skipped, functions mined, clusters found, coverage.

**Caching.** Cache per-file results in `.pcat-cache/` keyed by `sha256(file bytes)`, `CANONICAL_VERSION` and `SHAPE_VERSION`. Add `.pcat-cache/` to `.gitignore`. `--jobs` uses a process pool; results must be identical with any value.

## 4. Part B — fragments

Mine blocks inside functions to find idioms that never become whole functions.

- Candidate statements: `for`, `async for`, `while`, `try`, `with`, `async with`, `if` (with its `elif`/`else`), and `match`, at any depth.
- Minimum size: `--min-fragment-nodes` (default 25).
- Normalize each fragment on its own: rename names that are bound anywhere in the enclosing function (parameters and locals) to `v0`, `v1`, … in order of first appearance within the fragment; leave free names alone; then apply the same literal placeholders as shape matching.
- Cluster by fragment fingerprint exactly as in Part A, with ids prefixed `fr-`.
- **Suppress redundancy:**
  - Drop a fragment that is an entire function body (that's already a function cluster).
  - If a fragment cluster's members are all contained in members of a larger fragment cluster with the same occurrences, report only the larger one.
- Fragments get their own ranked section in the report, separate from functions.

## 5. Part C — promote

```
pcat promote <cluster-id> --report <dir>/report.json --id <pattern-id> [--member N]
```
- Only function clusters (`fn-…`) can be promoted in v2. For a fragment cluster, fail with a message saying fragments can't be promoted yet, and show the member's location so the user can extract it into a function by hand.
- Representative member: the largest exact-fingerprint sub-group, then the shortest file path, then the lowest line number. `--member N` picks a specific member by its index in the report.
- Reuse the `pcat add` machinery for the representative's source file and function. Methods can't be promoted (classes aren't supported in patterns); fail with a clear message.
- The report path and source files must still exist; if the source file changed since mining (hash mismatch), fail and ask the user to re-run `pcat mine`.
- Promote creates the pattern folder exactly as `pcat add` does. It does not approve anything; approval stays the normal git flow.

## 6. Report format

**`report.json`** (byte-identical across runs on the same inputs; no timestamps; sorted keys; `indent=2`):
- `canonical_version`, `shape_version`, `settings` (all flags used)
- `inputs`: each path, plus git commit SHA and tag if it's a git repo
- `stats`: files scanned, files skipped (by reason), functions mined, functions filtered (by reason), fragments mined
- `coverage`: covered and near-covered counts and percentages, with catalog ids
- `function_clusters` and `fragment_clusters`: id, score, occurrences, node_count, distinct files and inputs, catalog match (if any), shape text, exact sub-groups, members (path relative to its input, line range, qualified name, decorators, exact fingerprint, file hash)
- `skipped_files`: path and error

**`report.html`**: one self-contained file, no external requests. Summary at top (stats and coverage), then two ranked tables (functions, fragments). Each row expands to show the shape text and a list of members with file and line. Readable on a phone width. Generated only from `report.json` data so the two never disagree.

## 7. Part D — benchmark on open-source code

- Add `scripts/benchmark.py`: shallow-clones these repos at pinned release tags into `.bench/repos/` (gitignored), runs `pcat mine` on all of them together, and writes the report to `.bench/report/`.
  - `psf/requests` at `v2.32.3`
  - `pallets/flask` at `3.0.3`
  - `fastapi/fastapi` at `0.115.0`
  - If a tag doesn't exist, use the closest release tag and record it in `DECISIONS.md`.
- Run it once and write `docs/benchmarks/v2-results.md` (committed): versions mined, run time, stats, coverage, the 10 top-scoring function clusters and 10 top fragment clusters (id, occurrences, short description of what the code does), and a short honest assessment of whether the repetition found supports the project's idea. Note anything that looks like noise and how filtering could be improved.
- The benchmark is not part of `pytest` or CI.

## 8. Tests

Use small fixture files committed under `tests/fixtures/miner/`. At minimum:
- Two functions differing only in names, comments and literal values → same shape fingerprint, different exact fingerprints, same cluster with two exact sub-groups
- `True`/`False`/`None` differences → different shapes
- Methods, nested and async functions are all mined; decorators don't change fingerprints
- Each filtering rule excludes what it should, and its flag turns it off
- An unparseable file is skipped and listed, and the run still succeeds
- Clusters below `--min-occurrences` aren't reported; ranking and cluster ids are deterministic
- Fragment renaming: a parameter used in the fragment is renamed; a global isn't
- Fragment redundancy suppression and whole-body exclusion
- Catalog coverage: a copy of a seed pattern's function is covered; a literal-changed copy is near-covered
- `report.json` is byte-identical across two runs and with `--jobs 1` vs `--jobs 4`
- The cache is used on a second run and invalidated when a file changes
- `report.html` is generated, contains every cluster id, and references no external URLs
- `promote`: creates a valid pattern from a function cluster; rejects fragment clusters, methods, and changed source files with clear messages
- Existing seed fingerprints and all v1/v1.1 tests are unchanged
